# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

printerr prints price labels for Erzgebirge woodcraft. It is a Vue 3 + TypeScript single-page app that runs entirely
in the browser, with no backend: products are kept in IndexedDB and printed to A4 through the browser's own print
dialog. It is deployed to GitHub Pages.

## Language

The UI text, README, `docs/`, the example spreadsheets and the spreadsheet column headings are **German**. Code,
identifiers, comments and tests are **English**. German column headings appear only in `src/lib/schema/columns.ts`
(plus the German field names used in diagnostics in `build-labels.ts`). Everything else uses the English field names.

## Commands

Node version is in `.nvmrc` (24); the package manager is pnpm.

```sh
pnpm dev                              # http://localhost:4300
pnpm test:unit                        # Vitest in watch mode
pnpm test:unit run                    # single run (what CI does)
pnpm test:unit run src/lib/price.test.ts        # one file
pnpm test:unit run -t "part of a test name"     # one test
pnpm type-check                       # vue-tsc --build
pnpm lint                             # oxlint, then eslint; both run with --fix and change files
pnpm format / pnpm format:check       # oxfmt
pnpm build                            # type-check + vite build -> dist/
pnpm beispiele                        # regenerate beispiele/*.ods
```

CI (`.github/workflows/pages.yml`) runs `pnpm test:unit run` and `pnpm build` on every push to `main`, then publishes
`dist/`. If a test fails, nothing is deployed.

Lint is split on purpose. Oxlint (`.oxlintrc.json`) handles all JS/TS logic. ESLint exists only for Vue `<template>`
rules and enforces the SFC block order `template, script, style`. Formatting (`.oxfmtrc.json`): no semicolons, single
quotes, 120 columns, no trailing commas, sorted imports and Tailwind classes.

`src/components/ui/` is generated by the shadcn-vue CLI (`components.json`), and lint and format ignore it. Add
components through the CLI instead of writing them by hand.

## Architecture

Layers, from pure logic to UI:

- `src/lib/`: pure functions with no Vue and no DOM, fully unit-tested. Price rules, spreadsheet parsing, catalogue
  mutations and pagination all live here.
- `src/infra/`: browser adapters, meaning IndexedDB (`catalog-store.ts`, which falls back to localStorage),
  `safe-storage.ts` (storage access that never throws) and the text-measuring sandbox (`dom-measurer.ts`).
- `src/composables/`: thin reactive wrappers around `lib/`. Each one exports a `createX(deps)` factory, which tests use
  to inject storage, and a module-level singleton that the app uses (`catalogState`, `selection`, `settings`).
- `src/print/`: the label and sheet components, their hand-written millimetre CSS, and `geometry.ts`.
- `src/components/`: the two workspaces, `PrintWorkspace` and `data/DataWorkspace`. Both are toggled with `v-show` so
  that measurements survive a tab switch and Cmd+P works from either tab.

### Two data shapes, joined by `resolveLabel`

- **Catalog** (`lib/catalog/types.ts`) is what the shop edits and stores. A `Product` points at shared `Part`s
  through `ProductPart` links. A link can override the part's price for that one product. All records are readonly:
  every change goes through a pure function in `lib/catalog/mutate.ts`, and `use-catalog.ts` applies it by replacing
  a `shallowRef` wholesale, then saves after a debounce. Forms edit a `Draft<T>` copy.
- **Label** (`lib/types.ts`) is what gets printed. It is flat and self-contained. `lib/catalog/resolve.ts` builds labels
  from the catalogue, and everything after that step (price view, auto-fit, pagination, `PriceLabel`) knows only
  about `Label`.

The pipelines:

- **Import:** `.ods` → `readOds` → `buildLabels` → `catalogFromLabels`. `buildLabels` never throws; it returns the
  labels that parsed plus `Diagnostic`s. `catalogFromLabels` merges repeated add-on rows into one `Part`, keyed by
  article number and otherwise by normalised name. Where a row's price differs, it becomes an override.
- **Export:** `catalogToOds` writes a flat sheet that can be read back without loss. `toBackup` and `parseBackup`
  handle the complete JSON backup.
- **Print:** `resolveLabels` → `computePriceView` (`lib/price.ts`) → `createAutoFit` → `paginate` → `PrintSheet` /
  `PriceLabel`.

### The exhibition price rule (`lib/price.ts`)

If any add-on is marked as exhibited, the large price is the base price plus every exhibited add-on. The base price
then moves into the breakdown underneath. German price-display law (PAngV) requires this, and the whole app depends
on it. Money is always integer cents and is never added up as a float.

### Geometry and fitting

`src/print/geometry.ts` is the single source of truth for millimetres. `PriceLabel` binds its values as CSS custom
properties (`labelCssVars` / `sheetCssVars`), and auto-fit derives its measuring boxes from the same functions.
Don't hard-code label dimensions in CSS.

Every size is calibrated for the reference label, a quarter of A4 (105 × 148.5 mm, which is **not** ISO A6), and
scaled to whatever grid is chosen:

- horizontal measurements scale with the label width;
- vertical measurements scale with the label height;
- type scales with the smaller of the two.

Grids always divide A4 exactly. The number of slots per sheet comes from `slotsPerSheet(style)`. The
`SLOTS_PER_SHEET = 4` in `paginate.ts` is only a fallback default.

`lib/fit-text.ts` is a pure font-size search that takes the measurer as an injected argument, because jsdom reports
every dimension as zero. The real measurer is a detached `contain: strict` sandbox. It can't measure inside the
preview, because the preview is scaled with `transform` and that distorts every reading. Measuring happens whenever
the rendered set changes, not in `beforeprint`, which cannot wait for async work. Measurements are invalidated once
`document.fonts.ready` resolves.

The label font (Source Serif 4) is embedded in `src/assets/fonts/` rather than linked, so every machine gets the same
metrics and therefore the same fitted sizes.

## Print constraints that bite

The README section "Dinge, die nicht offensichtlich sind" gives the full reasoning for each rule. In short:

- The preview and the printout are the same DOM. Only the scaling wrapper is neutralised for print.
- JavaScript makes the page breaks, not the browser: there is one block element per A4 sheet, because of
  `break-inside` bugs in grid and flexbox.
- The page break goes on `.sheet-scaler`, not on `.sheet`. It is `break-before` each following sheet and never
  `break-after`, because a break after the last sheet makes Firefox print an empty page.
- In print, a sheet is 0.25 mm shorter than A4 (drivers report 296.9 mm), and nothing else may stand next to the
  sheets. Otherwise a nearly empty extra page follows each sheet.
- Cut lines and everything else must print without "background graphics" turned on. Draw them with borders and
  typography, never with CSS backgrounds.

`src/print/print-css.test.ts` guards the cut-line and page-break rules by reading `print.css` as text.

## Pitfalls

- **Never store Vue proxies.** IndexedDB serialises with `structuredClone`, which throws `DataCloneError` on a proxy.
  Unwrap form data with `toRaw`, and nested arrays separately (see `plainProduct` in `use-catalog.ts`), because
  `toRaw` unwraps only the top level.
- **Stored settings and state are untrusted.** Storage keys share the `printerr:v1:` prefix. Values are normalised or
  clamped when read (`normalizeStyle`, the guard on the `mode` tab), because a file opened from disk shares one
  origin with every other local page.
- **The spreadsheet format is a contract.** If you change columns in `lib/schema/columns.ts` or the writer, also update
  `docs/tabellen-format.md` and rerun `pnpm beispiele`. `src/lib/example-file.test.ts` imports the generated files end
  to end.

## Tests

Vitest runs with jsdom and without `globals`. `src/test/setup.ts` registers Testing Library's `cleanup` and stubs the
browser APIs that reka-ui needs, such as `matchMedia` and `ResizeObserver`. The Vitest config leaves out the Tailwind
plugin on purpose. Component tests use `@testing-library/vue` and `user-event`. Tests that read files from disk use
`process.cwd()`, which Vitest pins to the project root.

## Commits

Commits follow Conventional Commits (`feat:`, `fix:`, `docs:`, `ci:`). The subject line describes what changes for
the shop, in plain language, for example `feat: choose how many labels share a sheet, from one to sixteen`. The body
explains why.
